## 已确认问题

### F-001：频段峰频率允许超出实际频谱的范围，部分范围会被静默截断

- 严重性：高；状态：已复现；证据：E-002、E-003。
- 位置：`backend/app/algorithms/peak_frequency/runner.py:48`、`:56`，`compute.py:56`。
- 实际数据复现：35–40 Hz 参数被接受，却返回 `PEAK_FREQUENCY_NO_BIN`。25–40 Hz 返回 25 Hz、`quality=clean`，但实际频谱仅 1–30 Hz，搜索没有覆盖 30–40 Hz。
- 原因：只检查 Nyquist，加载器仍用固定 1–30 Hz，计算器只对两者交集取最大值。
- 影响：前者无结果；后者可能对未完整搜索的频段给出“有效”结果。本记录扩展输出频谱后，25–40 Hz 的峰恰好仍为 25 Hz，不能据此说明其他记录也不受影响。
- 建议：明确算法支持域；若保持 1–30 Hz，入口拒绝越界；若扩展支持域，同时明确预处理范围、输出范围、质量门和科学版本，不只扩大显示轴。
- 同类问题：`band_ratio/runner.py:49`、`:56` 接受分母 30–50 Hz，却返回 `BAND_RANGE_INVALID`。同样需在执行前拒绝或真正支持。

### F-002：频段峰频率将搜索频段误写为滤波频段

- 严重性：中；状态：已复现；证据：E-001、E-003。
- 位置：`backend/app/algorithms/spectral_snapshot.py:31`、`peak_frequency/runner.py:37`。
- 8–13 Hz 搜索配置的执行快照写 `bandpass_hz=[8,13]`，实际频谱证据是 `[1,30]`。
- 原因：通用快照通过 `low_hz/high_hz` 字段名推断滤波参数，但这里二者代表选峰范围。
- 影响：返回数值可正确，但持久化滤波快照不准确，不能凭该快照复现；结果自身的频谱证据仍记录了真实滤波。
- 建议：快照由模块显式提供实际预处理设置，搜索范围单独记录；检查静态、动态和拒绝点的溯源。

### F-003：PSD 陷波参数执行正确，但公共快照错误

- 严重性：中；状态：已复现；证据：E-002、E-003。
- 位置：`backend/app/algorithms/spectral_snapshot.py:10`、`:35`。
- 本记录 1–50 Hz PSD，分别关闭陷波及选 60 Hz：实际滤波证据分别为 `null`、`60`，独立复算通过；执行快照二者仍写 `50`。
- 原因：快照按高切是否达到 45 Hz 自动推断陷波，没有读取显式配置。
- 影响：不是这两次 PSD 的计算误差，而是 Run 元数据自相矛盾。共享该快照的其他模块也应检查，不能把本次未测试的配置直接认定正确。
- 建议：显式陷波配置优先，默认策略仅用于没有该参数的算法。

以上建议尚未实施，需要独立修复及回归，不应改完公式后直接覆盖本次审计结论。

## 范围与剩余风险

这是后端数值和执行审计，不是 WPF 实际点击／渲染验收，亦不是临床或生理有效性证明。没有穷举 28 列、所有范围、滤波组合、采样率及所有记录。

4 秒 Hann、50% 重叠和先剔除再平均的 Welch 已核对；其频率网格为 0.25 Hz，FAA 2 秒 epoch 为 0.5 Hz。频率 bin 间距不等于分辨相邻峰的实际能力。步长末尾不足 1 秒不自动生成新动态点，本记录最后动态端点 149 秒；静态最后不足一个完整 epoch 的尾部不独立计算，不做零补全冒充真实输入。

IAPF 当前是简化的 log-log OLS 去背景与 Peak/COG 估计，拟合 R²/error 只是证据、没有额外的显著性门。数值复算通过不能证明每个低信噪比窗口存在可靠的生理 Alpha 峰；5 秒窗通常只有一个有效 4 秒谱段，动态稳定性需要另行研究。

生产质量判断主要针对预处理后信号，不能据此声称已排除全部原始硬件饱和、眼动、肌电或临床伪迹。还应注意个体化指标与固定频段功率比不是同一个指标。平台的“官方”是平台内置定义，不表示得到外部学术机构或医疗认证。

本次工具/文档属于诊断整理，`skip_specs=true`：没有改变科学、API 或 UI 行为。回滚仅删除本次新增的两份 scripts、诊断测试和两份审计报告，不涉及原始记录及生产实现。
