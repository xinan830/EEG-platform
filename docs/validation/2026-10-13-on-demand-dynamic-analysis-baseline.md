# 按需动态分析基线（2026-10-13）

## 目的

记录小时级合成 EEG 的科学计算基线，区分连续零相位预处理与单个 PSD
窗口计算耗时。该数据只用于性能测量，不包含真实 EEG，也不代表完整 API/WPF
端到端延迟。

## 方法

- Python 3.13，NumPy/SciPy 当前锁定环境。
- 3,600 秒、200 Hz、32 通道、`float64`，固定随机种子 `20261013`。
- 合成数据为零均值高斯信号，振幅约 `2 µV`。
- 预处理：连续 `1–30 Hz` 零相位带通，不启用陷波。
- 窗口：5 秒 Welch PSD，输出 `1–50 Hz`，随机抽取 100 个位置。
- 只读内存数组；没有 SQLite、artifact、HTTP、WPF 和磁盘读写。

## 结果

| 指标 | 结果 |
|---|---:|
| 样本数 | 720,000 |
| 原始/预处理数组 | 184.3 MB / 184.3 MB |
| 连续预处理 | 0.424 s |
| 单窗 PSD p50 | 0.232 ms |
| 单窗 PSD p95 | 0.303 ms |
| 单窗 PSD 最大值 | 0.920 ms |

## 结论与限制

按需窗口减少的是未请求窗口的 Welch 计算和结果发布；在当前科学契约下，首次
请求仍可能等待整段连续预处理。上述结果不能推导出首窗 API 延迟，也没有验证
长记录文件解析、缓存、SQLite、队列容量、进程重启或 WPF 绑定。进入 P3 前仍
需要在真实记录和完整服务链路测量注册、预处理、首窗、后续窗、发布/读取、CPU、
峰值内存和临时磁盘，并把原始记录 hash 与历史 Run 可读性纳入验收。
