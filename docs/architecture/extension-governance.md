# 本地扩展治理边界

本地脑科研工作台允许用户和平台描述算法模块的来源与科学接口，但这不是插件加载系统。模块 manifest 只是一份可校验的元数据，不能传输、保存或执行代码。

## 当前可用能力

```text
GET  /api/extensions/capabilities
POST /api/extensions/validate
```

Manifest 支持三种来源：`local_official`、`research_template`、`user_private`。每份声明必须给出：模块 ID、名称、来源、平台兼容范围、工程验证状态、输入/输出科研类型、声明式权限和执行模式。

当前执行模式只有：

- `closed_definition_graph`：只能指向现有的闭集算法定义图；
- `metadata_only`：只描述信息，不能声明权限。

“权限”仅用于未来审计和设计讨论，当前不授予运行时能力。允许的声明是读取 recording 元数据或读写派生 artifact；它们不等价于文件系统权限。

## 明确不支持的能力

当前接口不会安装、持久化或执行第三方模块。它拒绝未知字段，因此不能接受 `python_source`、脚本路径、网络 URL 或命令。以下能力均为 `false`：任意 Python、网络访问、子进程、文件系统访问、签名插件、市场、多租户和组织权限。

这不是一项技术缺失，而是本地科研工作台的安全边界。现有算法继续由后端的闭集节点和不可变定义版本执行。

## 未来 Python 插件的前置条件

若未来确有必要执行第三方 Python，必须先创建单独的安全 change，并至少实现独立进程、只读输入、临时目录、禁网、CPU/内存/超时限制、依赖白名单、审计日志和可撤销的安装来源。在此之前，不得把 manifest 扩展为代码载体。
