核心隔离原则：实时分析不经过离线 Run，也不污染原始录音文件；显示滤波只服务波形显示，绝不作为科学算法输入。采集侧 5 个实时算法（rbp、psd、stft、rbp-topomap、psd-topomap）共享 DEFAULT_SPECTRAL_GATEWAY / five_band_shares() / TopomapService 科学原语及 Review 图表呈现样式，但仍保持独立的实时短生命周期契约。

二、桌面端 WPF 与 Python 后端技术连接详图

展开下方详图可查看跨进程 HTTP 二进制传输边界、有界队列、协调器调度与模块级连接关系。

A · 实时采集与实时算法：一处采集，三条独立异步消费链

AcquisitionCoordinator 串行检查设备样本连续性后，将同一批原始数据分发给三条互不阻塞的异步路径。即便后端繁忙或实时算法过载，也只返回结构化 overloaded / unavailable 状态，绝不反压阻塞设备读取或写盘。

B · 离线回溯与科研分析：Review 按需窗口与持久化批量 Run

离线侧严格区分持久化全量/批量 Run（PersistentRunQueue）与交互式回溯按需窗口（DynamicWindowService），两者共用 algorithm_runtime 官方算法注册表与 ScientificComputeCoordinator 计算隔离。

工程红线与前后端职责边界清单

1. 时间、单位与通道红线

  • 后端内部连续信号统一 float64、形状 (samples, channels)、单位 V；API 波形返回统一 µV。
  • 离线与调试时间统一为文件绝对秒；采集实时分析统一以采集会话首样本 S0 为原点计算 start_s / end_s。
  • ch_names 与列顺序严格同步，禁止按 UI 显示名猜测信号角色。

2. 实时调度与失败显式表达

  • 实时协调器固定 4 个全局 worker 槽，每算法最多 1 个在飞窗口，禁止无界队列。
  • 跨缺口或被覆盖的样本区间直接返回 unavailable；算力繁忙返回 overloaded + skipped_windows。
  • 严禁用零值或复用旧值掩盖缺失数据；revision 单调递增杜绝乱序覆盖。

3. 模块划分与跨端边界

  • 桌面端 10 个业务模块：Acquisition、Devices、Channels、Montages、Projects、Recordings、Events、Review、Algorithms、Settings。
  • 科学计算零侵入 WPF：桌面端只负责采集、显示投影、交互状态与配置校验；科学计算统一归 Python 后端。
  • 业务文件软上限 400 行，超线需在 docs/code-size-policy.json 登记评估。
