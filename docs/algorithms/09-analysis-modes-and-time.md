# 静态、动态与运行策略

静态/动态是算法执行模式；全量/按需/组合是动态结果的获取策略。支持动态不自动说明支持单窗执行、组合或某个复用方向。

| 策略 | 含义 |
| --- | --- |
| 全量分析 | 为所选分析范围规划并计算完整窗口序列，再消费 Run 结果 |
| 按需分析 | 根据游标请求当前所需窗口，缓存与去重由共享窗口服务管理 |
| 全量分析 + 按需分析 | 前台按需响应，后台计算完整序列；两条生命周期协调且取消相互隔离 |

各算法分别声明最小/默认窗口、step、Partial、尾窗与缺样规则。共享层按这些声明调度，不强行让 FAA、STFT、Brainbeat 使用相同窗口。复用能力与验证方向见[管理矩阵](official-algorithm-management.md)。

## 时间边界

请求区间、实际分析范围、当前计算窗口、游标与可视历史范围分别保存。科学窗口使用录制相对绝对样本坐标；秒数经采样率及既定取整规则转换，不能只比较“相差不到一个样本”。

UI 刷新节奏不决定算法窗口。慢请求返回时不能覆盖更新后的游标、导联或配置；同一窗口重复请求可以复用，但必须验证源、配置、范围、单位、实现与结果格式身份。

Partial 是当前模块明确支持的不完整初始窗；Rejected/Unavailable 必须有原因，数值不以零替代。执行状态、科学质量和窗口结果状态分别判断。

切换导联、滤波或科学参数应形成新的科学请求身份；缩放和显示历史长度不属于科学参数。详见[数据链路](01-data-pipeline.md)。
