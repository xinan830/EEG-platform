# 高密度导入录音回溯加载修复验收（2026-11-26）

## 问题与根因
用户导入 264 路、512 Hz、311 秒 BDF 后，点击回溯长时间无反馈，页面长时间停留在“正在生成目标滤波波形”。桌面日志显示该录音多份元数据/原始样本请求重叠，原始样本请求通常耗时约 5 秒，而显示滤波二进制请求约 45–55 毫秒。

主瓶颈是后端 `_read_acquisition_signal_view`：128 路 CAR 的每一路公式引用相同的 128 路参考池，却对每个依赖重新扫描绑定表、源通道表及历史表。带 cProfile 的一次 `require_recording` 为 19.67 秒、约 874 万次 `_field` 调用；该时间包含剖析开销，不能当作无剖析计时。桌面还在首帧完成之前才 Show 窗口，且初始异步打开期间没有统一防重入。随后读取下一块时，前一块的过滤状态文案仍被保留。

## 修复
- 后端单次解析建立保留全部候选的标签/原生索引，逐个不同来源校验一次。重复、缺失、历史、类型、单位错误继续拒绝；没有跨请求缓存，也没有取消源验证。
- MainWindow 回溯组合/释放按职责移至 `MainWindow.Review.cs`，元数据打开防重入，首帧准备之前显示回溯窗；项目入口在打开时禁用重复动作。加载中关闭取消原会话，初始化不会继续发布。
- 新增读取源数据阶段，滤波完成后切换显示准备文案，避免下一块读取期间仍报告正在滤波。阶段计数器保留录音真实 FirstSampleCounter。
- 原始时间、V/float64、通道顺序、导联公式、滤波及科学算法、HTTP/WebSocket 结构均不变。

## 补充修复：首帧与跳转空引用

性能修复后，同一导入录音仍提示 `Object reference not set to an instance of an object`。此前后端真实文件计时和不带导联的 WPF 夹具没有覆盖这一桌面缺陷，不能据此认定真实桌面已完整通过。

### 根因与修复

- 真实导入的 CAR 快照包含完整通道配置与公式，但没有工作站保存时的 `ChannelConfigurationFingerprint` / `Fingerprint`。反序列化后指纹为 null；构造显示源身份时，`MontageProfileFingerprint.Create` 对其调用 `Trim()`，首次显示及跳转均抛出空引用。独立诊断捕获了该调用栈。
- 新增 `RecordingMontageSnapshot.Resolve`，在主导联和目录条目进入目录去重、显示及缓存身份生成之前校验必要字段；合法快照缺失的指纹使用既有规范算法生成。已有显式指纹保留，源 JSON 不重写，原始样本和导联公式不改变。无效条目显示诊断原因，不影响同目录其他合法导联。
- 前台读取/跳转异常增加录音、回溯会话、请求代次及绝对目标时间的日志；不记录 EEG 样本。
