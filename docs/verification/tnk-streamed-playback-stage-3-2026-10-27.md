# TNK 流式回顾第 3 章验证记录（2026-10-27）

## 实现结果

- TNK 详情区单独显示最新已接收分析窗口结束时间、相对播放游标的有符号滞后，以及历史覆盖状态。迟到事件按真实窗口时间合并，较早结果不会覆盖较新窗口的侧栏值。
- 窗口历史与投递断档保持有界、去重。超过 600 窗口会显式报告历史不完整；精确投递缺口会重新确保缺失区间终点的规范窗口，后端继续按 TNK 状态顺序重放。补齐结果覆盖缺口后才清除断档；补算失败会留下“不完整”状态。
- 历史投影在后台计算，UI Dispatcher 只合并并发布最新投影快照。被合并的是重复的 UI 通知，接收的每个科学窗口仍先进入有界历史。
- 普通曲线和 RBP 堆叠曲线共用前缀校验；前缀未变时只追加尾部。迟到补齐改变历史前缀或保留窗口裁剪时才重建 SciChart 数据序列。自动跟随范围继续推进，手动历史平移保持不变。

## 自动验证

- TNK 桌面专项：45 项通过，包含窗口历史、结果身份/去重、滞后/覆盖、投递恢复、动态窗口协调、导航与图表范围测试。
- TNK 投递后端专项：11 项通过（事件契约与投递 API）。
- 桌面 Release 主项目构建：通过，0 错误；存在当前 .NET 预览 SDK 与 NU1701 第三方包兼容警告。
- OpenSpec strict validation：通过。
- `git diff --check`：通过。

桌面测试项目中存在工作区未跟踪的 `Channels/ElectrodeLocationClientTests.cs`，该文件的测试 handler 返回类型不匹配，导致不带过滤的测试构建失败。本次 TNK 专项通过只在本次命令中排除此单个未跟踪文件，没有修改它。

## 本机 CPU 微测量

在当前 Windows/.NET 10 主机上，使用 100、300、600 个历史点；每个点数重复测量 500 次。微秒值是纯 .NET 展示投影/append planner 测量，不包含 SciChart 渲染、WPF Dispatcher、波形绘制或后端计算。

| 历史点数 | 线图前缀追加判定均值 | RBP 堆叠展示投影均值 |
| ---: | ---: | ---: |
| 100 | 4.37 µs | 26.87 µs |
| 300 | 11.27 µs | 52.40 µs |
| 600 | 21.46 µs | 68.81 µs |

测量说明：线图追加判定仍需比较现有前缀，成本随历史点数增长，但在 600 点保留上限下，本机均值约 21 µs，当前证据不足以支持引入更复杂的修订索引。RBP 前缀追加路径不再替换整个 `XyDataSeries`；微测量覆盖纯展示序列投影，不代表 GPU/SciChart 实机帧时延。
