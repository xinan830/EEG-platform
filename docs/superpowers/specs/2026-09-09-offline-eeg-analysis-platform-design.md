# 离线脑电分析平台设计

## 目标

将 `D:\AI\Work\eeg-process-main` 的离线分析与可视化体验迁移为可在浏览器使用的 EEG 分析平台。第一阶段支持 BDF/EDF 导入、通道映射、可复现的分析结果和报告展示；不连接 eego USB、FreeBCI 串口或实时 LSL 数据流。

## 范围与非范围

### 本阶段范围

- 导入 `.bdf`、`.edf` 文件，并持久保存原文件和录制元数据。
- 读取采样率、通道列表、时长、已有 annotation 事件，允许用户将源通道映射为 Fz、Pz、Oz，以及可选的 F3、F4。
- 复用桌面项目的科学计算口径：MNE 预处理、Welch PSD、150 µV 伪迹窗、IAPF 峰中心优先/CoG 兜底、30 秒窗与 5 秒步长、三次候选中位数锁定、BrainBeat、疲劳、HAI、RBP、1/f 斜率和 FAA。
- 提供逐样本数据时间轴上的离线回放结果、综合冥想指数、IAPF/PSD 拟合、各项趋势和事件时段报告。
- Vue 单页工作台复刻源程序的信息层级：录制选择与控制、EEG 波形、综合分/IAPF、分析标签页、事件与时段报告。

### 明确不在本阶段范围

- 浏览器直接访问 USB、串口、eego SDK 或硬件阻抗。
- 实时 LSL、实时 BDF 录制、跨机器设备发现。
- 多用户鉴权、云对象存储、分布式队列和长时任务调度。
- 用分析分数推断心理状态或医疗诊断。

## 关键决策

### 后端是唯一的信号处理权威

浏览器只上传文件、提交映射和渲染结果。FastAPI 服务负责读取文件与计算，使用 Python、MNE、NumPy、SciPy、specparam；Vue 不复制或近似实现 EEG 算法。这样同一录制在本地桌面项目和 Web 服务中可以使用同一组输入、阈值与频段语义比对。

### 离线回放以数据时间驱动

后端产出以 `elapsed_s` 表示的数据时间。前端回放速度只改变显示节奏，不改变样本窗口、分析值或事件位置，避免墙上时钟导致的 2x/4x 图表形变。

### 第一版分析同步执行，但接口按任务资源设计

`POST /api/recordings/{id}/analysis` 在第一版同步返回可查询的分析资源，适合单机文件与开发验证。响应结构必须包含 `analysis_id`、状态和结果 URL；未来替换为后台队列时保留这些资源语义，Vue 无须重写。

### 仅从已声明映射使用关键通道

Fz、Pz、Oz 为核心分析通道，缺任一时拒绝启动完整分析并返回可理解的验证错误。F3/F4 为 FAA 可选通道：二者缺任一时仍完成其他分析，并将 FAA 标为不可用。系统绝不根据列位置猜测电极名称。

## 后端 API

| 方法与路径 | 用途 | 成功结果 |
|---|---|---|
| `GET /api/health` | 服务健康检查 | 服务名与状态 |
| `POST /api/recordings/import` | 上传 BDF/EDF | 录制 ID、文件元数据、通道列表、annotation |
| `GET /api/recordings` | 获取录制目录 | 分页前可先返回完整列表 |
| `GET /api/recordings/{id}` | 获取单条录制和映射 | 元数据、可用通道、最近分析 |
| `PUT /api/recordings/{id}/mapping` | 保存 Fz/Pz/Oz/F3/F4 映射 | 规范化映射 |
| `POST /api/recordings/{id}/analysis` | 使用映射执行分析 | `analysis_id`、状态、摘要 |
| `GET /api/analyses/{id}` | 获取完整结果 | 时间序列、频谱、报告与诊断字段 |

上传接口只接受 `.bdf` 与 `.edf` 后缀；文件解析失败、通道重复映射、核心通道缺失以及数值无效均返回结构化 4xx 错误。服务器绝不把用户原始文件名当成存储路径。

## 分析结果契约

分析资源至少包含：录制与算法版本、通道映射、IAPF 锁定值、实时 IAPF 时间序列、信号质量、PSD/1-f 拟合字段、综合分与子指标趋势、RBP、疲劳、HAI、1/f 斜率、事件时段报告以及 FAA 报告。

所有趋势点都包含 `elapsed_s`。无足够干净片段或不满足 IAPF 门槛时，保留诊断字段和失败原因，而不是伪造 IAPF 或用零填充。FAA 无 F3/F4、数据不足或干净 epoch 不足时返回 `faa: null` 与原因。

## 前端体验

初始页面显示文件导入和历史录制。选择录制后显示通道映射；映射通过后进入分析工作台。

工作台保留源程序的核心视觉结构：左侧为带事件标记的多通道波形与分析标签页，右侧为录制控制、综合冥想指数、实时/锁定 IAPF、脑负荷及事件段报告。离线回放控制包含播放、暂停、重播、1x/2x/4x；它只消费已完成分析的结果，不重新运行算法。

图表组件必须在无分析值、部分通道不可用、分析失败和结果加载中显示明确状态，不把缺失值画成连续的零线。

## 数据与安全

SQLite 仅保存元数据、映射、事件和分析 JSON；原始录制保存在 `storage/recordings/<uuid>.<ext>`。开发环境不做账户系统，但 API 不暴露任意文件路径，也不支持按路径读取文件。上传大小限制、保留期和生产备份策略在上线前按部署环境补充。

## 测试与验收

- 后端：pytest 覆盖上传校验、映射校验、BDF/EDF 元信息、关键算法纯函数、分析结果序列化和 API 生命周期。
- 前端：TypeScript 类型检查与生产构建必须通过；对 API 客户端和状态转换写单元测试。
- 回归：使用固定合成 EEG 和小型脱敏录制夹具，验证 IAPF、质量门、FAA 无效条件、事件时段边界和数据时间轴。
- 手动验收：导入一份带 Fz/Pz/Oz 的 BDF/EDF，在浏览器中完成映射、分析、播放和各报告查看；2x/4x 下同一个数据点的 `elapsed_s` 和分析值保持不变。

## 第二阶段演进

新增 `acquisition-agent`：运行在设备所在 Windows 主机，复用现有 eego/FreeBCI/LSL 接入层，向后端发布认证后的数据与控制事件。现有录制与分析 API 保持不变，实时会话以与离线分析结果相同的数据模型补充增量帧。
