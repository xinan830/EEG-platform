# 滤波状态检查点缓存

## 目的

静态窗口必须从文件起点建立因果滤波状态，才能与连续播放及拖动定位逐点一致；每次请求都从零开始会使长文件后段定位越来越慢。

## 实现

- `DisplaySignalFilter` 增加深复制的 `snapshot()` / `restore()`，缓存 DC、陷波和带通状态。
- `RecordingService` 按 `recording_id + 滤波参数 + 必要源通道顺序` 建立进程内检查点索引。
- 检查点目标间隔为 10 秒；实际保存为跨过目标边界的 50 ms 块末位置，因此不依赖采样率能否整除 10 秒。
- 窗口读取从不晚于目标起点的最近检查点继续处理，输出数值契约不变。

## 边界与风险

- 首次访问或缓存未命中仍需从文件起点处理；服务重启后缓存丢失。
- 缓存只保存滤波器状态，不保存原始或处理后 EEG 数据，原始文件仍只读。
- 当前已完成进程内 LRU 容量淘汰；尚未做多进程共享和真实长文件压力基准，这些是后续性能验收项。

## 验证

- `test_filter_snapshot_restore_matches_continuous_stream` 验证恢复状态后的输出与连续流一致。
- 后端全量测试：42 个通过。
