# 2026-09-10 EEG 波形回放性能管线

## 事实与根因

- 原回放每 50 ms 将整屏 `Float64Array` 转为普通数组；21 通道、10 秒窗口、500 Hz 时每帧复制约 105,000 个数值。
- Vue 对波形数组深度监听，Canvas 每帧重置实际像素尺寸并重画全部样本。全选通道时主线程会同时承担复制、响应式遍历、JSON 解析和全量绘制。

## 实现

- `WaveformSweepBuffer` 的帧改为只读共享 `Float64Array`；外层帧引用更新，采样数组不再复制。
- WebSocket 波形块采用 `float32-le-interleaved-v1`：`float64 elapsed_s` 头部加按样本交错的 µV `float32` 数据。控制、错误和元信息仍为 JSON。
- 浏览器将二进制数据直接写入 TypedArray 环形缓冲，不创建二维普通数组。
- Canvas 仅在物理尺寸变化时重设尺寸；采样密度超过屏幕像素宽度时按像素列绘制 min/max 包络，保留尖波而不进行均值抽点。
- 包络极值按文件时间顺序连接为连续折线，避免每像素列独立短线形成“点阵”视觉。
- 调试台每秒显示渲染 FPS、平均绘制耗时、慢帧数、二进制数据包速率与解码入缓冲耗时，用于区分前端绘制与后端送帧问题。
- 连续回放改由 `Web Worker + OffscreenCanvas` 持有环形缓冲、抽点和 Canvas 绘制。主线程仅把 WebSocket `ArrayBuffer` 以 transferable 所有权转移给 Worker，保留 Vue 用于工具栏、时间轴与弹窗。
- 默认完整扫屏视图改为增量绘制：每个数据包只清除游标后的 0.2 秒空白带并绘制新到采样；缩放、拖拽、尺寸变化时才执行一次完整重绘。这样避免每 50 ms 反复扫描 21 通道的完整 10 秒窗口。
- 流式会话开始时，时间轴显式同步服务端 `start_s`；从非零秒开始回放不会误用静态预览窗口而退回全屏重绘。
- Worker 初始化前将通道名复制为普通数组，且流会话元数据使用浅响应式保存；避免 Vue `Proxy` 进入 `postMessage` 后触发 `DataCloneError` 并中断播放。
- 缩放边界按流式环形缓冲的当前 `sweepStartS` 计算，并由 Worker 对视窗起点做钳制；第一屏结束后缩放不会把视窗错误送回 0 秒造成空白。
- 时间轴拖拽边界使用缩放后的 `viewDuration`，并由时间轴容器统一捕获指针；缩放后蓝色视窗仍可完整拖动。
- `App.vue` 的显示设置状态机拆入 `useDisplayControls.ts`，恢复 400 行代码规模约束。

## 协议与兼容性

- 首条 `info` 消息增加 `waveform_encoding: "float32-le-interleaved-v1"`。
- 静态窗口 HTTP API 不变，仍返回 JSON 波形，避免影响调试台和初始阅图。
- 此次服务端与当前前端必须一起发布；不支持二进制帧的旧前端不能消费新的连续回放流。

## 验证与剩余风险

- 新增前端二进制解码、TypedArray 零复制缓冲测试，以及后端二进制编码、WebSocket `send_bytes` 契约测试。
- 未做浏览器性能基准截图：当前浏览器自动化环境不可用。性能收益基于已移除的全窗口复制、深度遍历、JSON 解码和逐采样绘制热路径；仍应在目标机器上对 21 通道、实际采样率文件记录 FPS 和内存。
- 当前高性能渲染路径需要 Chromium 系浏览器的 `transferControlToOffscreen`。不支持该能力的浏览器会明确提示，不能将其当作性能验收环境。
- 更高通道数或多用户并发的下一阶段：`OffscreenCanvas/Web Worker`、多分辨率缓存，以及后端按窗口读取而不是每回放会话全文件载入内存。
- 本次已完成 `OffscreenCanvas/Web Worker`。后续性能工作集中于多分辨率缓存、60Hz 扫描游标动画，以及后端按窗口读取而不是每回放会话全文件载入内存。
