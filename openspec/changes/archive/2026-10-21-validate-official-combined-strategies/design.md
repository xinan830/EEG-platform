## Context

见 proposal.md。当前官方 manifest 共用能力构造器；矩阵冻结整个 manifest 指纹。已有反向复用测试部分只对照缓存本身，冻结 combined 摘要不证明实际组合执行。

## Goals / Non-Goals

目标是将每项 validated 声明绑定可重跑的专项测试。仅验证当前科学身份，保留 unsupported 方向。不变更数值基线或重新实现公式，不以合成小文件证明大文件性能。

## Decisions

- 使用现有真实 WPF 录制文件 reader、SQLite Run queue、窗口 service 和共享 compute coordinator，在临时目录创建无身份合成输入。对照组先执行无缓存全量；组合组共享同一只读源，在后台全量存续时执行预览。用事件同步确保生命周期重叠，避免依赖机器速度的 sleep。
- 每算法比较全量全部数组及逐窗证据，对预览检查真实范围、质量、科学身份与对应全量窗口。取消前台订阅不取消后台全量。重叠和数值一致分别断言，不能以两种单独模式通过相加。
- PSD/STFT 额外断言实际复用计数，再比较无缓存基准；损坏证据应重算。沿用现有异常/取消测试。
- 能力构造器接受显式证据路径，由各算法 manifest 申报；缺省仍为未验证。测试证据必须绑定当前算法参数项，禁止因共享框架存在就将未来算法自动提升。
- 原有冻结数组保持不变；能力声明变化只更新 manifest 指纹与专项证据。报告记录环境、命令、限制和差异，测试临时 artifact 归临时目录所有，不提交源数据或构建缓存。
- WPF 使用逐算法策略测试验证请求及生命周期，实际桌面操作需单独记录，不能由单元测试替代。

## Risks / Trade-offs

- 线程测试可能挂起 → 所有等待有超时，finally 释放事件及 worker。
- 不同算法窗口/质量契约不同 → 依据实际返回范围匹配，不强制所有算法共享指标结构。
- 合成信号可能不可用 → 显式验证状态，保留 null，不伪造数值。
- 未执行真实桌面操作 → 在报告明确保留该限制，不冒称 UI 实机验收。

## Migration Plan

先通过专项测试，再更新声明与矩阵。无持久数据迁移；回滚本轮软件变更。全套后端、WPF、OpenSpec 和规模检查通过后交付；退役清理的归档单独保持可追溯。

## Observed defect

新增组合测试复现后台 provider 初始窗口快照遗漏稍后完成的预览窗口：ensure_window 返回 ready 记录后，旧逻辑仍调用 create_attempt，导致终态错误被转换成科学窗口不可用。修正为重新核实持久化状态，已有完成结果走原校验复用；只有确实属于本 full Run 的新 producer 才返回待计算。终态在检查/创建之间发生变化时重新读取记录，其他 ValueError 继续抛出。未改变数值计算或放宽完整性检查。
