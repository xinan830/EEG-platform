# 按需优先与全量后台补齐任务

## 规格与契约

- [x] 建立组合离线调度策略的后端和 WPF 状态契约；确认 `full` / `on_demand` 科学模式不扩展为第三种算法模式。
- [x] 明确按需会话、后台 Run、配置代数、结果来源和取消令牌的所有权与生命周期。
- [x] 定义并冻结 `ScientificConfigKey`、`AnalysisPlanKey`、`WindowKey` 和 `RequestGeneration` 的字段、序列化形式及相互关系；确认 `RequestGeneration` 不进入科学缓存身份。
- [x] 为支持按需或跨模式复用的算法定义 `PreparedSourceContract`，覆盖准备范围、有效范围、滤波/参考/gap/边界语义、单位、状态、manifest 和数值容差证据。
- [x] 明确 durable single-flight 的共享计算所有权、消费者订阅、优先级提升和协作取消规则；订阅取消不得默认取消仍被其他消费者需要的计算。
- [x] 明确后台最低执行份额、资源预算和不可中断工作单元观测指标；不在没有测量依据时承诺固定帧率或零等待。
- [x] 明确完整 Run 的窗口 coverage、quality、failure、artifact manifest/checksum 和终态门禁；局部窗口不得标记为完整结果。
- [x] 明确稳定后端幂等身份、重复点击/重试/恢复行为以及显式“重新运行”如何生成新的尝试身份。
- [x] 补充 PSD/STFT 以外算法的能力矩阵，标明是否支持组合策略、跨模式复用和全局预处理依赖。
- [x] 明确不支持按需能力时 WPF 只提供全量策略并展示不可用原因，不静默回退或自动启动全量。
- [x] 运行新 change 的 OpenSpec strict 校验，确认当前规格未与已归档执行模式契约冲突。

## 后端调度

- [x] 增加有界的交互优先调度协调点，复用现有动态窗口 worker 和 batch Run worker，不创建无界线程池。
- [x] 在两个 worker 之上增加共享的 `WindowKey` 协调点，实现 durable single-flight、消费者计数、所有权转移和按需优先级提升。
- [x] 为后台动态 Run 增加窗口边界让出、交互需求检查和结构化等待/取消日志。
- [x] 保证按需请求仍是 latest-only、同窗口去重，旧响应不能覆盖新目标。
- [x] 验证连续交互压力下后台 Run 获得配置的最低执行份额，并记录让出、等待、执行、不可中断持续时间及资源拒绝原因。
- [x] 验证按需取消只释放订阅，不取消仍被后台 Run 或其他订阅者需要的共享计算。
- [x] 验证后台全量取消不影响按需预览；按需失败不影响后台全量。
- [x] 验证 CPU、内存、临时磁盘和活动任务上限，记录后台最低执行份额，避免长期饥饿。

## 缓存与结果来源

- [x] 保持科学缓存身份与调度策略解耦，覆盖记录、导联、通道、滤波、参考、窗口、参数、版本和实际范围。
- [x] 实现 `PreparedSourceContract` 的身份和状态校验；准备范围、边界状态或 manifest 不匹配时拒绝复用并返回结构化 miss reason。
- [x] 复用 PSD/STFT 已验证的按需到全量窗口结果，并覆盖部分命中、损坏回退、质量状态和取消。
- [x] 设计并验证完整 Run 反向提供按需窗口的只读窗口索引；若本轮风险过高，明确延期而不猜测数组位置。
- [x] 为每个结果记录 `producer_mode`、`result_scope`、`served_from`、窗口范围、单位、质量和不可变 `provenance_id`；禁止把局部完成显示为完整结果。

- [x] 根据算法能力声明禁用不适用的策略并显示结构化原因；不支持按需时不得自动创建按需会话。
