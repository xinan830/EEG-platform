## Context

现有 `electrode-locations` 能力已经提供标准模板 XYZ 和头顶二维坐标，通道配置也会保存位置来源与快照。现有算法结果和数据回放已经各自拥有时间窗口与结果质量契约，但没有一个跨算法的空间结果边界。详细行为以本变更的 `specs/analysis/eeg-topomap/spec.md` 为准。

## Goals / Non-Goals

**Goals:**

- 建立一个由算法结果适配器供数、由统一地形图组件消费的跨算法契约。
- 让地形图跟随数据回放工作区的统一时间协调器，并具备旧请求丢弃和不可用状态。
- 复用现有电极位置解析和通道配置快照，保留单位、参考方式、质量和 provenance。
- 先接入 RBP 的逐通道逐频段输出，验证公共框架后再接入其他算法。

**Non-Goals:**

- 不新增 RBP、PSD 或其他脑电指标公式。
- 不在 WPF 中计算功率、频段或插值科学输入。
- 不把双极导联强行映射为某个电极，也不把标准模板位置宣称为实测电极位置。
- 不改变原始录音、通道配置、参考方式、历史结果或实时采集链路。
- 不引入新的缓存系统；五频段并列图只消费同一窗口响应。

## Decisions

### 1. 使用算法适配器连接通用地形图

每个算法保留自己的科学运行模块，只提供一个面向地形图的 typed adapter：指标/频段标识、逐通道值、单位、时间窗口、算法版本、参考方式、质量状态和空间资格。地形图模块不导入具体 RBP、STFT 或 TNK 公式。

选择适配器而不是在每个算法中复制绘图代码，是为了让坐标校验、质量排除、插值边界和请求竞态只有一份实现。替代方案“每个算法各自做一张图”会产生不同的时间、单位和缺失值语义，因此不采用。

### 2. 由后端准备可追溯的空间输入，WPF 只做呈现

后端使用结果中的原始通道身份与保存的电极位置快照组装空间输入，完成空间资格校验，并返回明确的数值单位、参与通道、排除原因和空间方法。WPF 使用统一时间协调器请求当前窗口，使用顶部视图选择器在 RBP 堆叠历史图和独立地形图页面之间切换；地形图渲染五个头部、各自颜色标尺和等值线，不重新计算指标。

插值属于结果空间投影的一部分，第一阶段由后端执行或返回确定性的有界网格；前端不得自行选择另一套插值算法。这样同一个结果在算法工作区和数据回放页具有相同科学语义。

### 3. 首版采用五频段并列头皮图

RBP 注册 Delta、Theta、Alpha、Beta、Gamma 等已有结果，后端一次返回同一窗口的五个频段，界面以五个独立标准头皮图并列展示。每个频段拥有自己的色标和等值线，切换不再触发请求，也不重复计算。

这样避免用户在频段之间反复切换，也保证 RBP 堆叠历史图与空间地形图拥有清晰的独立页面。五个图共享坐标和窗口身份，但不共享一张画布；地形图按每行两个图排列。

### 4. 以窗口身份做竞态保护

每次请求携带录音身份、绝对 `window_start_s`/`window_end_s` 和时间协调器代次。响应只有在仍匹配当前窗口和代次时才能发布；旧响应直接丢弃。不存在“用上一窗口结果填空”的回退。

### 5. 位置来源保持标准模板语义

地形图继续使用现有 `mne.colin27_1020` 位置来源和 `map_coordinates`。响应和 UI 明确显示“标准模板位置”；手工二维图示位置只能作为图示覆盖，不改变标准 XYZ、信号身份或分析参考。

### 6. 统一导联位置快照和分析身份

通道配置中的编辑态只存在于工作区草稿；用户显式保存/应用后，系统生成新的 montage 版本并保存完整位置快照。RBP 或其他算法运行创建时捕获该版本，结果身份和缓存键包含 `montage_id`/版本。运行期间修改通道位置不会就地移动已有结果；必须由新的运行重新计算。这样修改位置不会要求用户手动修改算法版本号，也不会污染历史结果。

### 7. 统一显示投影而不是复制绘图参数

`MapX/MapY` 统一采用同一归一化坐标系，头部中心、半径、前后方向、左右方向、鼻子和耳朵由一个共享几何契约提供。通道配置图和地形图只负责各自的业务叠加：通道配置可显示全部启用输入和 REF/GND 硬件标记，地形图只将满足空间资格且有有效数值的通道送入插值；两者不再各自定义 `RadiusScale` 或重新解析标准位置。

### 8. 迁移边界

迁移先覆盖通道配置图和 RBP 地形图，再让后续算法直接消费同一契约。删除旧的重复位置解析和局部几何常量；不保留双写、旧格式转换或“优先旧坐标、失败再用新坐标”的兼容路径。未保存的编辑态不进入分析，历史运行只读取其已绑定快照。

## Risks / Trade-offs

- [标准模板与真实帽体位置不同] → 在结果契约和界面中保留来源、版本和模板提示；不把它当作实测定位。
- [RBP 当前结果可能只有汇总值] → 先检查并补齐逐通道逐频段适配器；若没有逐通道值，明确返回不可用，不生成热图。
- [空间有效通道过少导致插值不稳定] → 设置最小有效点数、重复坐标校验和头部边界；失败返回结构化原因。
- [连续回放带来大量重绘] → 复用统一时间协调器的窗口发布节奏，五频段共享一次当前窗口请求，不新增独立轮询器。
- [低分辨率网格在头部边缘留下明显空白或大方块] → 后端使用 65×65 网格，并将插值头部边界（1.0）与标准电极内边界（0.92）分开记录；WPF 按响应网格边界绘制，电极点仍使用原始标准模板坐标。
- [双极结果被误读为空间电位] → 适配器必须声明空间资格；没有空间规则的双极结果一律排除。

## Migration Plan

1. 新增地形图公共契约、后端空间输入/投影边界和 WPF 可复用呈现组件，但不改变现有算法结果格式。
2. 为 RBP 增加第一个适配器，使用现有逐通道逐频段结果；没有满足条件的结果时只显示结构化不可用状态。
3. 在数据回放页面接入统一时间协调器、RBP 图表选择器和每行两图的五频段呈现，完成自动化契约测试与人工验证。
4. 其他算法按同一适配器契约逐个接入；不需要为每个算法建立新的地形图控件。
5. 若迁移失败，移除地形图入口和适配器注册即可；原有算法、回放和通道配置路径不受影响。

### 9. WPF 地形图渲染边界

画布收到新频段或尺寸后，在后台计算颜色范围、BGRA 位图和等值线几何，并冻结位图、裁剪几何、等值线和画笔。每次准备任务有独立代次与取消令牌；只有频段引用、画布尺寸和代次都仍匹配的快照才能发布到 Dispatcher。旧任务不能覆盖新结果。`OnRender` 只绘制已准备的快照、头部和电极标记，不执行网格遍历、边缘补绘或等值线计算。显示布局、频段顺序、颜色映射、边缘覆盖规则和后端科学数值保持不变。

回放 ViewModel 保持五个频段展示项的集合和项目实例稳定，只替换项目中的 Band 数据。协调器以 `null` 表示被取代的旧请求时，消费方忽略该返回，不把它当作显式清空；用户解除分析或工作区重置时才清空。这样 ItemsControl 不会因每个响应都换 ItemsSource 而卸载旧画布。

## Testing Strategy

- 后端契约测试：绝对时间窗口、单位、通道顺序、位置来源、质量排除、双极不可用和错误码。
- 空间投影测试：足够点、点数不足、重复坐标、边界外坐标和非有限输入。
- RBP 适配器测试：每个频段的逐通道值、算法版本和缺失结果语义。
- WPF 测试：频段切换请求、时间窗口竞态、旧响应丢弃、不可用状态和模板提示。
- 运行 `openspec validate --strict`、相关后端/桌面测试、`git diff --check`；工程验证不代替临床验证。
