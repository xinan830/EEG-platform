# 统一离线分析执行模式

## Why

离线记录既需要完整时间序列，也需要在长记录中快速查看当前游标窗口。两者应共享同一套科学算法和参数契约，避免为不同入口维护重复计算逻辑。

## What Changes

- 在已完成的 Recording 上明确 `full` 与 `on_demand` 两种离线执行方式。
- 全量模式继续计算指定范围内的全部窗口；按需模式只确保当前游标目标窗口。
- WPF 根据算法能力提供执行方式选择，保留全量默认、按需能力开关和历史结果兼容。

## 目标

在已完成的 Recording 上同时提供全量分析和按需分析。默认使用全量分析；只有算法显式声明按需能力且可用性策略允许时，用户才可以选择按需分析。后续 `enable-accepted-offline-analysis-selection` 将已验收模块默认开放，保留维护覆盖。

## 非目标

- 不引入实时采集分析。
- 不修改任何 EEG 算法公式、滤波顺序、窗口策略或质量门。
- 不把全量 Run 和按需窗口实现成两套科学计算代码。

## 约束

两种模式必须使用相同的算法配置和后端科学模块。执行方式只影响调度、加载和展示，不得改变数值语义。历史 Run 和原始记录保持可读且不可变。
