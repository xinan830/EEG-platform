## Why

算法详情页目前只把采集导联快照生成的通道名放进一个“分析导联”下拉框，导联配置本身不能切换。用户切换参考或平均导联后，页面必须同步更新可用分析导联，并让九个官方算法使用新导联信号重新计算，否则界面选择与科学输入会脱节。

## What Changes

- 在算法详情的分析对象区域增加“导联配置”选择，并以采集时的导联配置作为默认值。
- 展示采集时的历史导联目录，并接受客户端显式提交的当前兼容配置；后端依据该记录已保存的通道配置和实际源信号验证后，单独持久化为分析配置快照，明确区分来源，不修改采集文件。
- 让“分析导联”选项由当前导联配置和记录实际通道共同决定；切换配置时保留通道角色，替换为对应导联输出。
- 将导联配置身份、分析导联、映射指纹和公式纳入官方算法请求及 Run provenance。
- 导联配置变化触发统一的请求修订、旧请求取消/结果淘汰和九个算法重新计算；动态预览、全量、按需、组合路径使用同一联动规则。
- 保持原始采集文件、原始通道列、已完成历史 Run 和算法公式不变；科学计算仍由各算法后端模块负责。
- 对缺少源通道、配置快照不一致或算法不支持的导联，返回结构化不可用原因，不静默回退或复用旧结果。

## Capabilities

### New Capabilities

- `desktop/algorithm-montage-selection`: 算法详情中的历史导联配置选择、分析导联联动、请求修订和结果追溯。

### Modified Capabilities

- `desktop/wpf-official-algorithms`: 官方算法请求必须携带实际导联配置和分析导联，配置变化必须触发重新计算。
- `analysis/official-algorithm-execution`: 官方算法运行上下文必须使用并记录经过验证的历史导联投影。
- `signal/montage-reference`: 记录范围内的导联配置和通道映射必须显式、不可变、可验证；算法选择不得使用回溯显示导联代替分析导联。

## Impact

- WPF 算法工作区的分析对象 ViewModel、共享分析卡片、请求构造和九个算法结果刷新路径。
- WPF 记录注册响应及后端记录注册/导联目录接口。
- 后端 acquisition montage reader、官方 Run 配置与 provenance。
- 记录 manifest 的导联配置快照模型；原始样本文件不变。
- 需要增加 WPF/API/后端契约测试、导联投影测试、配置切换竞态测试和九算法联动验收。
- 这是新的输入契约；旧的仅有 `channel` 的请求不获得新的导联切换语义。
