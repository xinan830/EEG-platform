## Context

Live display filtering is causal and stateful. Applying coefficients from a
new configuration to state from an old configuration would make the waveform
transition scientifically opaque. Raw capture history is already bounded and
separate from raw persistence.

## Goals / Non-Goals

**Goals:**

- Apply live display changes without blocking the device capture loop.
- Seed replacement filter state with at most two seconds of contiguous raw
  samples and show only values generated by the new configuration.
- Preserve raw data, gaps, V/float64 units, and non-EEG columns.

**Non-Goals:**

- Reconfigure the amplifier, retroactively change a raw recording, or claim
  that the display setting is offline scientific preprocessing.
- Refilter through a sample-counter gap or invent missing warm-up samples.

## Decisions

- The C# client supplies only bounded raw context; Python remains the single
  filter implementation. A second C# formula was rejected to prevent drift.
- Configuration revisions label outgoing requests and returned batches. The
  renderer accepts only the current revision, so a slow old HTTP response
  cannot reintroduce old-filter data.
- Replacing the display history avoids presenting one trace as though it used
  one configuration when it did not. The new trace begins with the returned
  warm-up context.

## Risks / Trade-offs

- [Short history at the start of recording] → Use all available contiguous
  samples, even if fewer than two seconds; do not delay acquisition.
- [Local Python is unavailable] → Continue raw capture and explicitly fall
  back to unfiltered display rather than fabricate output.
- [Rapid repeated changes] → The single analysis dispatcher serializes the
  requests and revision filtering discards stale results.

## Migration Plan

1. Deploy compatible API fields with zero/empty warm-up defaults.
2. Desktop clients that do not send warm-up retain prior session behavior.
3. Rollback removes live reconfiguration; all raw recordings stay valid.
