# 设计：统一离线分析执行模式

## 模式边界

- `full`：通过既有 `/api/runs` 执行完整动态 Run，计算指定范围内全部窗口并持久化完整 artifact。
- `on_demand`：通过既有动态窗口 API，优先确保当前游标目标窗口，结果按窗口持久化。

两种模式共享算法目录、参数快照、导联/通道解析、滤波和算法模块。WPF 不计算科学结果。

## 选择规则

WPF 动态参数区显示执行方式。默认选择“全量分析”。只有结果处理器声明按需窗口能力且对应 `BRAIN_WPF_ON_DEMAND_<ALGORITHM>` 已启用时，才显示“按需分析”。能力关闭后不得静默切换到按需；已选择按需时应回退到全量并清理旧预览。

## 状态和结果

切换执行方式会清除当前展示投影并重新提交配置，但不改变科学参数。全量结果和按需结果仍沿用各自的既有 API 响应和 provenance；本变更不宣称两种存储已经共享缓存，后续单独收口缓存身份。
