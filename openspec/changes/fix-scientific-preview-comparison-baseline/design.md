# Design

## Context

根因与范围见 `proposal.md`。当前 `build_preprocessing_preview_window` 仅返回科学处理后结果；WPF 叠图把因果显示曲线改成浅灰作为参照。请求固定 1000 点，科学线固定 2 DIP；实际科学准备、极值显示压缩和普通因果显示已经分别有唯一所有者。

已授权录音的相同片段关闭全部增强策略后仍复现差异；本次科学数据与独立 SciPy 计算一致，因此不调整滤波数学。项目已有多个未提交修复，尤其坏段共享报告与 ICA 缺口溯源，必须保留其实现和测试。

## Goals / Non-Goals

**Goals:**

- 配对预览在服务层统一准备，两侧科学过滤契约可验证，前端只呈现返回值。
- 普通彩色线路与科学比较状态互斥呈现；一致的科学输出不因重复画线显得更粗。
- 配对请求保持有界、可取消、可追溯，复用现有科学缓存，不新增持久化。

**Non-Goals:**

- 不改实时线路、算法公式、科学预处理顺序或已审查 ICA 成分；不把滤波器调到肉眼相似。
- 不将科学预览设为算法输入，不增加科学频带设置，不实现连续播放科学比较。
- 不承诺任意宽时间窗的压缩图保留全部高频细节，也不把工程一致性称为临床有效性。

## Decisions

### 1. 同一个科学门面准备前后两侧

在预览用例中固定共同规格（当前 1–50 Hz、陷波 50 Hz、Q=30、既有零相位）；使用同一解析后的记录与导联快照，通过既有 `prepare_continuous` 准备：

```text
不可变原始录音 + 分析导联快照 + 相同科学滤波规格
  baseline：坏导 none、坏段 none、去伪迹 none
  processed：用户所选策略，按既有科学顺序执行
  -> 校验来源、采样率、总样本范围和共同滤波一致
  -> 裁剪同一个半开样本窗 -> 按输出身份配对 -> 共同显示压缩
```

这里只比较共同来源身份与共同滤波指纹；两侧有效导联/预处理身份可以因坏导策略而不同，不能误要求完整准备指纹相同。增强策略全关时两侧引用同一准备对象；启用时复用既有 LRU/单飞，最多需要两种规格的准备结果，不保证第一次没有额外读盘或滤波。

选择基线关掉所有增强策略，而非仅关 ICA：这样差异代表整个所选方案的效果。坏导先插值/排除再重参考，后续沿用现有滤波、坏段和去伪迹顺序，不把该简图误实现成“先滤波再插值”。

不选“把本地改成零相位”或“只把线变细”：前者影响普通阅图和实时设计，后者无法消除真实数值差异。

### 2. 一次响应交付完整配对数据

保留现有 POST 预览路径与预处理请求结构，响应更新为明确版本 `scientific-preview-comparison-v1`。建议类型结构：

- 公共元信息：记录与源身份、请求分析导联及快照身份、实际起止样本与绝对秒、采样率、`unit=µV`、`ScientificFilterSpec.to_evidence()` 及指纹。
- `baseline` / `processed`：各自有序通道、每通道时间/µV 值和有效预处理证据；处理侧保留现有插值/排除信息、ICA 模型复用及 `artifact_removal_validity`。
- 配对压缩元信息：共同索引算法版本、点数预算、缺口边界允许超预算、不对科学输入重采样。
- 两侧增强规格经规范化后相同的显式标记，用于全部关闭时单次画线。该标记不由前端比对浮点值推测。

内部仍为 sample-major float64/V；仅 API 展示边界转为 µV。前后端类型同时更新，搜索所有构造、fake client、序列化测试和导出引用。旧响应、缺任一侧、滤波证据不符、无序/重复时间、未知版本均明确拒绝，不回退为原有比较。科学错误保留现有稳定错误码和 request_id；必要新增码先写契约测试，不按错误文案分支。

### 3. 通道与显示压缩采用共同坐标

基线有序输出列表作为比较行顺序，按既有通道身份和大小写规则匹配处理后输出，不去掉导联后缀猜配对。排除的处理输出显式为空并保留基线行；意外新增或不能对应的处理输出拒绝配对，不能挤到其他通道行。插值涉及 CAR/双极依赖时沿用公式级标记，在灰色线角色之外以已有徽标/说明表示，不改成第三种曲线角色。

扩展既有 extrema helper：共同分桶中取两侧各自 first/min/max/last 的样本索引并排序去重；同时按两侧有限性边界切分，保留缺口开始及恢复。每个索引读取两侧各自的真实样本，禁止线性插值补齐。未匹配行仅压缩基线。压缩方法改为版本化配对方法，保留未受影响的 ICA 迷你波形 helper 行为。

`max_points` 定义为每条配对输出的共同时间网格目标，不分别无限取并集；按每桶最多 8 个候选索引决定桶数，缺口边界为正确性允许超出软预算。密集缺口须遵守已有响应/窗口资源限制并显式失败，不能靠删缺口降载。

密集缺口硬预算：每迹线最多 16000 个时间点，整份响应两侧所有时间/幅值数组累计最多 1000000 个标量（null 计入）。逐行压缩时提前检查，序列化前以 HTTP 422 / `PREPROCESSING_PREVIEW_LIMIT_EXCEEDED` 显式拒绝并要求缩短时间窗；不删缺口、不补零。此限制仅保护配对预览，ICA 迷你波形保持原逻辑。

点数预算由实际 plot area 宽度计算，例如 `clamp(ceil(plotWidthDip * 2), 1000, 4000)`；不新增公开配置，宽度未就绪时不发请求。视口裁剪不再强制至少 1 秒，应支持已有亚秒阅图，避免极窄视口请求大窗后被压缩。宽度改变只在预算改变时合并刷新，保留既有短延迟和取消机制。

### 4. 唯一绘图状态控制两种视图

普通颜色/样本点样式由现有普通阅图拥有；新增数据只在现有科学图层内维护一对 series：浅灰基线、深灰处理后，名义线宽均 1 DIP，共用轴、灵敏度与 NaN gaps。增强全关时两组数据仍可验证相同，仅绘制深灰一条避免重复加粗。

科学对比模式状态：

| 状态 | 波形与说明 |
| --- | --- |
| 关闭 | 原有彩色阅图 |
| 加载 / 失败 | 彩色阅图；明确“科学对比加载中 / 不可用” |
| 成功且当前 | 隐藏彩色 series 和普通 sample markers；只显示科学浅灰/深灰 |
| 播放 / 在线临时导联 | 清除科学 series，彩色阅图并说明暂停 |
| 退出 / 页面释放 | 清除配对响应与 series；恢复原样式或释放 |

不能仅把普通彩色曲线淡化来冒充基线。所选导联无后端快照时拒绝请求，不得静默按 Raw 请求。发布前按完整通道身份校验当前显示行在科学基线中存在；普通曲线、采样点和叠图共用匹配判断，异步帧也不得因过期/不匹配比较而隐藏。排除状态以处理侧精确 excluded_output_channels 为准，不用字符串截断推断双极依赖。原子提交两侧数据；选择变更、视口变更和尺寸预算均纳入请求发布身份。画布异步刷新普通缓存帧或更新样式时仍须尊重当前成功的比较状态，不得重新露出第三层曲线。

顶部高通/低通/陷波仍只作用普通阅图；科学模式增加紧邻图例“科学对比：零相位 1–50 Hz，陷波 50 Hz（Q=30）；顶部滤波仅用于彩色阅图”。灵敏度和走纸速度仍共享几何，科学模式不重置位置。显示密度、进入/退出比较和普通滤波变化不使 ICA 确认失效。

### 5. 兼容、存储与规模

不写原始目录、不迁移数据库、不持久化新的科学副本，准备数组由现有服务资源所有者释放。预算只影响序列化和显示，不进入科学缓存身份；真实数据图和详细结果仅存 `.artifacts/`。

实现前核对当前 api/DTO 文件是否接近 400 行；如需要按“预览契约”职责拆出相应模型文件，并更新调用方，不机械切段。保留既有坏段报告和 ICA 缺口说明。不能把其他尚未归档变更标为本次已完成；有重叠规格时核对当前工作区并在验收记录说明依赖。

## Risks / Trade-offs

- [首次启用两种准备可能增加耗时与内存/磁盘占用] → 复用有界缓存和已有资源预算，禁用策略复用同一对象；测冷/热请求，不承诺零成本。
- [极值包络不能保留所有波形细节] → 统一两侧规则、公开预算与缺口例外，支持已有放大阅图；不把压缩视图当作精确重采样。
- [坏导处理改变参考池并影响多路输出] → 保留处理前独立基线和完整处理证据，说明这是整个策略的效果。
- [灰色曲线遮挡与来源误读] → 明确图例、等线宽、关闭策略时单绘；恢复彩色与失败状态纳入测试。
- [生产者与客户端版本不一致] → schema 严格校验、部署/回滚成套完成，失败时彩色阅图可用且不声称科学比较成功。

## Migration Plan

1. 先补配对 API/DTO、全关等值及展示状态的失败回归，明确改变是预览语义而非算法语义。
2. 实现后端配对准备/压缩，再同步 WPF DTO、状态与图层；开发中不混用旧客户端验收新响应。
3. 跑后端和桌面相关测试、编译、规模检查与 strict OpenSpec 校验；用真实录音对同时间片做数值与图形验收并匿名记录。
4. 更新当前架构与界面说明中受影响条目，归档前同步主规格；未获明确指令不提交推送。
5. 回滚时成套恢复预览生产者和 WPF 消费者，无需恢复源文件或数据库；不得以旧比较逻辑作为静默兼容分支。
