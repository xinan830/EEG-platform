# Proposal

## Why

当前科学叠图把因果显示滤波波形淡化后，与零相位科学预览比较；即使两侧都是 1–50 Hz、50 Hz 陷波且坏导、坏段、去伪迹全部关闭，也存在明显差异。真实录音相同片段已复现，不能把这种差异呈现为增强科学处理的效果。

## What Changes

- 普通阅图保留现有彩色通道、顶部显示滤波和播放线路。进入科学对比时隐藏普通波形，原子展示浅灰“科学滤波基线”与深灰“科学处理后”；退出或暂停对比时恢复普通彩色阅图，不同时叠三组线。
- 两条科学曲线复用后端现有连续预处理门面：同一不可变录音、同一分析导联和样本范围、同一科学滤波规格；仅处理后应用用户选择的坏导、坏段和去伪迹。
- 固定保留当前预览科学滤波 1–50 Hz、50 Hz 陷波、Q=30、现有零相位语义；顶部显示滤波不改变科学比较或算法配置。
- 配对结果携带可校验的时间、单位、通道顺序、科学滤波与两侧处理证据；保留坏段和 ICA 重建不可用的区分。增强处理关闭时复用同一个准备结果并保证逐样本一致。
- 统一两侧极值包络的分桶和时间坐标，依据实际绘图区宽度确定点数预算；统一线宽，保留真实缺口。
- **BREAKING**：科学预览 HTTP 响应升级为显式版本的配对结果，后端与唯一 WPF 消费者及测试夹具同步更新；不静默回退到旧的“显示线对科学线”。

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `signal/preprocessing`：定义同源、同滤波的科学前后配对预览及其证据、缺口、压缩和失败语义。
- `desktop/recording-review`：定义普通彩色阅图与浅灰/深灰科学对比的互斥呈现、视口预算和生命周期。

## Impact

- 后端：`services/preprocessing_preview.py`、`services/preview_envelope.py`、`api/preprocessing.py` 及相关契约和集成测试；复用 `OfflineScientificPreprocessingService.prepare_continuous` 和现有缓存，不新增滤波器或算法执行线路。
- 桌面：`PreprocessingContracts`、HTTP 客户端校验、`ReviewPreprocessingViewModel.Preview`、科学叠图图层、画布绘图区尺寸通知、预处理弹窗说明及相应夹具/生命周期测试。
- 科学契约影响：仅明确预览比较语义，不改滤波数学、算法参数、坏导在重参考之前的顺序、坏段检测规则或 ICA 拟合/应用；两侧导联输出受坏导策略影响时按身份匹配而非按列号配对。
- 非目标：实时采集/硬件、在线临时导联参与科学计算、连续播放科学叠图、可配置科学预览频带、新增 ICA 算法、提交推送 GitHub。
- 迁移与回滚：无需数据库或原始文件迁移；生产者、消费者、测试和文案成套更新或回滚，原始录音与已有算法结果不变。旧/不完整配对响应明确拒绝，恢复彩色阅图并说明对比不可用。
- 验证：先写配对响应和禁用策略等值回归，再实施；覆盖缓存复用、导联排除/插值、坏段、ICA 证据、竞态、恢复彩色；最后用已授权真实录音相同时间窗验收。私人数据仅进入 gitignored `.artifacts/`，公开报告匿名化。
- 文件规模：实现前逐文件确认 400 行软上限与现有登记；按请求模型/配对预览/画布呈现的实际职责评估，不机械拆分。
