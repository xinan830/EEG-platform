# Proposal

## Why

采集界面目前只有原始采集与显示处理，缺少用户已确认需要的实时算法结果。为避免把新需求混入已完善的离线回溯链路，本变更只为采集期增加独立的 RBP 实时分析支路，并将结果临时呈现在采集界面。

## What Changes

- 新增采集实时分析能力：预览与录制状态均可运行首个算法 RBP；分析分支不得阻塞采集、原始数据写入或现有波形显示。
- 新增后端实时分析执行契约：规定输入批次、通道筛选与顺序、采样坐标、连续性/缺口、窗口、预处理、质量、结果身份、错误及生命周期语义。
- 实时分析结果消息升级到 `live-analysis-update-v2`，显式携带计算所用导联修订号；桌面端与后端同步升级，拒绝旧导联迟到结果。
- 采集界面只展示当前采集会话的临时实时结果；停止/会话结束后清理，不保存为 Run，不进入项目分析结果或回溯流程。
- 现有离线 RBP、算法回溯、原始记录格式、显示滤波与 UI 波形输入保持原有行为。

## Capabilities

### New Capabilities

- `desktop/acquisition-live-analysis`: 采集会话中的实时分析启停、隔离、临时结果展示与清理行为。
- `analysis/live-analysis-execution`: 后端对采集实时数据执行算法的输入、处理、结果和失败契约。

### Modified Capabilities

无。现有 `desktop/acquisition-core` 已要求分析队列有界且过载/失败不得阻塞原始采集；现有离线 RBP 与算法回溯规范不应因实时支路而改变。

## Impact

- 影响桌面采集模块的会话控制、分析队列消费与采集界面临时结果呈现，以及后端实时分析服务/算法适配。
- 复用当前 RBP 公式与质量规则的前提是完成实时预处理等价性验证；若处理范围、滤波状态或窗口语义不同，必须使用明确的实时实现身份与证据，禁止冒充 `official-rbp-v4` 离线结果。
- 不新增持久化 Run、数据库迁移或公共离线 API 兼容层；若实现需要新的本地 HTTP/IPC 消息，应以有版本/类型字段的显式契约描述并纳入变更范围。
- 无离线记录迁移；兼容性目标是既有采集、保存、显示、回溯消费者均不变。
