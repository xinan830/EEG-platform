# 按需优先与全量后台补齐

## Why

离线 EEG 回溯同时有两种真实需求：用户需要立即查看当前游标附近的窗口，科研分析又需要最终得到整个区间的完整时间序列。单独使用全量分析会让长记录在首次展示前等待较久，单独使用按需分析又不会自动覆盖用户没有访问过的窗口。

当前项目已经具备 `full` 与 `on_demand` 两条科学执行路径、统一的窗口身份和部分跨模式结果复用能力。下一步不应再复制算法或重做数据层，而应增加一层调度策略：按需窗口优先服务当前交互，全量 Run 在后台持续补齐。

## What Changes

- 增加组合离线调度策略“按需预览 + 后台全量”，但不新增科学算法模式；后端科学执行模式仍只有 `full` 和 `on_demand`。
- 保留“仅全量”和“仅按需”作为显式策略，避免后台计算被用户误触发。
- 让按需目标拥有高于后台全量窗口的调度优先级，并在窗口边界提供协作让出和取消检查。
- 在 WPF 中分别展示当前预览状态和后台全量进度、取消状态及结果来源，不让一个状态字段同时表示两条任务。
- 复用同一科学身份和已验证的窗口缓存；只有模块声明并通过数值验证后，才允许跨模式复用。
- 保留既有 `/api/runs`、动态窗口 API、历史 Run、artifact 和导出语义；新增策略不修改 EEG 公式、滤波、导联、窗口和单位。

## Scope

本变更覆盖离线 Recording 的动态算法回溯、后台 Run 调度、窗口结果来源选择、WPF 组合策略和相关测试。首期以 PSD 为垂直切片，并验证 STFT 的既有跨模式复用；其他算法只有在各自能力声明和数值证据满足时才接入组合策略。

## Non-goals

- 不接入实时采集分析，不把离线后台 Run 宣称为实时结果。
- 不重新实现 PSD、STFT 或其他算法，不在 WPF 中计算任何 EEG 科学数值。
- 不直接引入 Zarr、HDF5、Redis、LMDB、Rust、WebGL 或无限并发；存储迁移必须由独立的性能证据驱动。
- 不用固定 Halo 秒数替代连续预处理的科学验证，不把分块滤波结果默认为与全量滤波等价。
- 不把已完成的局部窗口宣称为完整 Run，不把显示层降采样结果用于正式算法计算。

## Compatibility And Migration

旧客户端仍可调用 `full` 或 `on_demand` 的既有接口。组合策略由 WPF 协调器分别创建一个按需窗口会话和一个完整 Run，不把组合名称作为新的科学 `execution_mode` 发送给算法模块。未声明按需能力的算法不得提供组合选项；用户必须明确选择“仅全量分析”后才会启动完整 Run。

关闭详情页时只释放本页面的按需订阅；已经启动的全量 Run 默认继续运行并保留其历史结果，用户必须通过明确的后台任务取消动作停止它。修改科学参数、导联、滤波或范围会生成新的科学身份，旧 Run 不被覆盖或静默复用。

## Scientific-Contract Impact

组合策略不得改变结果的科学含义。系统必须分开记录科学配置身份、分析计划身份、具体窗口身份和 UI 请求代数。当前游标窗口和后台全量窗口必须使用相同的采样点范围、半开窗口规则、滤波/参考上下文、质量门、单位、科学版本和实现身份。窗口复用必须验证完整身份、artifact 校验和、轴、shape、单位、质量和证据；验证失败时重新计算，不能返回损坏值。

按需和全量只有在满足 `PreparedSourceContract` 时才可共享连续预处理结果。该契约必须说明准备范围、滤波/参考语义、边界依赖、有效样本范围、准备状态和可验证身份；不得因为参数字符串相同就静默使用不同预处理上下文。

结果溯源至少区分：最初生产方式（`producer_mode`）、结果范围（`result_scope`）、本次提供来源（`served_from`）和不可变 provenance 标识。完整 Run 的完成还必须独立记录窗口覆盖状态、窗口质量状态、计算失败和 artifact 发布校验状态。

按需结果可以被全量 Run 复用的算法继续沿用已验证的适配器。全量 artifact 反向供按需读取属于后续独立能力，未建立窗口索引和数值验证前不得假设自动可用。

## Risks And Decision Gates

- 后台全量与按需计算共享 CPU、内存和磁盘。如果没有资源门和窗口边界让出，组合策略可能反而使拖拽变慢；首期必须采用有界并发和交互优先，而不是简单增加线程。
- 纯 LIFO 调度会使全量任务长期饥饿；调度器必须保留后台最低执行份额并记录排队、计算、发布耗时。
- 不同算法的预处理上下文不同。FAA、Brainbeat 等算法不能因为共享调度协议就自动共享 PSD 的连续预处理缓存。
- “零延迟”“16 ms”“比特级一致”等指标没有现成证据，必须改为本机测量和算法声明的数值容差。
- 在 PSD 的组合策略通过真实 Recording 验证前，不批量开放其他算法。

后台一个不可中断的计算单元可能长于用户可接受的交互等待；必须测量并记录最长持续时间，不能把窗口边界让出当作抢占式取消。

相同科学窗口可能同时被按需和全量请求；必须在共享协调点实现 single-flight 和所有权转移，不能由两个独立 worker 各自猜测去重。

## Rollback

组合策略可以按算法能力或 WPF 可用性策略关闭，立即回退到既有“仅全量/仅按需”选择。回退不删除按需窗口、完整 Run、历史 artifact 或原始记录；正在运行的后台任务按显式取消和现有恢复语义处理。

## Validation

完成定义包括：后端调度、缓存身份、取消和进度测试；WPF 组合策略、请求序列化、双任务状态、旧结果防覆盖和页面关闭测试；PSD 真实 Recording 的数值/单位/质量/provenance 对照；STFT 已有复用回归；Release build、全量测试、OpenSpec strict、文件规模检查和 `git diff --check`。人工验收必须单独验证拖拽、播放、暂停、全量后台进度、取消和重新打开页面。
