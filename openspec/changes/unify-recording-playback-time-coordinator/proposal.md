## Why

同一录音当前存在 Review 播放时钟、TNK 工作台播放时钟和动态预览计时器，虽然都使用录音秒数，却没有一个会话级权威游标。这样会让波形、算法目标和算法展示分别推进，造成时间漂移、重复请求和难以判断的滞后；现有请求协调器只能协调请求，不能替代时间所有权。

## What Changes

- 为一个打开的录音会话建立唯一的播放时间协调器，以录音相对整数样本游标作为权威坐标。
- 统一管理播放、暂停、定位、倍速、结束和上下文 generation，并发布有界的游标变化事件。
- 每个录音宿主工作区内，Review 波形、TNK 面板和算法详情页消费同一会话游标，不再各自创建播放时钟；独立窗口各自拥有自己的上下文，将来面板嵌入宿主时通过注入复用宿主上下文。
- 保留算法窗口请求协调器，但明确其只负责目标合并、取消、排队和结果身份校验，不负责推进时间。
- 将算法目标发布链路接通到真实消费者；移除或替换当前没有订阅者的伪共享事件。
- 保持波形显示和科学分析两条执行线路独立：时间协调器只发布目标，波形读取与算法计算仍由各自服务异步执行。
- **BREAKING**：删除 TNK 工作台内部播放时钟和旧动态预览计时器作为播放来源；算法窗口请求不再由独立算法时钟产生。
- 不改变后端科学公式、窗口规划、样本单位、结果格式或历史 Run/artifact 读取语义。

## Capabilities

### New Capabilities

- `desktop/recording-playback-time-coordinator`: 定义录音会话级唯一播放游标、控制命令、generation 和订阅事件。

### Modified Capabilities

- `desktop/recording-review`: Review 与算法详情必须共享同一录音会话游标，播放推进不得由页面或算法模块各自计时。
- `viewer/waveform-playback`: 波形播放消费统一游标，但波形读取和渲染仍保持独立执行。
- `analysis/on-demand-windows`: 动态窗口请求的 cursor 由桌面时间协调器提供；请求协调器不再拥有播放时钟。

## Impact

- 主要影响 WPF Review、TNK 详情工作台、算法目录动态预览和 Review/算法请求适配器。
- 后端只继续接收并校验 recording-relative `cursor_sample`；不新增后端播放状态或科学计算路径。
- 需要更新 WPF 组件测试、请求目标测试和架构文档；不修改原始 EEG、数据库结果或历史 artifact。
- 迁移期间不保留第二套内部播放 API；历史录音和现有完整 Run 继续按当前契约读取。
- 科学契约不变：秒仍为录音绝对时间，内部信号仍为 V/float64，窗口边界仍由后端规划。
