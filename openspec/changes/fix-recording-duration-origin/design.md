## Context
`AcquisitionCoordinator.RecordingFirstSampleCounter` 在首批录制数据被原始写入器接收后才有值。预览环形缓冲区可能已包含大量未记录数据。`Started`/`Resumed` 是有效段首样本，`Paused`/`Stopped` 是有效段末样本，均为包含端点的原始设备样本坐标。

## Decisions
1. 复用录制首样本提供器，起点未知时录制时长为零，不复用 `SessionFirstSampleCounter`。这表示尚未接收录制样本，而非掩盖错误。
2. `LiveDisplayTimelineTracker.Update` 显式接收录制起点；起点未知时仅维护实时显示锚点，不积累暂停/恢复状态。两个显示入口每次读取同一份录制起点供更新与计算使用。
3. 保留既有生命周期优先计算和未提供边界调用方的暂停累计逻辑；真实工作区已注入采集层边界，不增加新的时钟或状态所有者。
4. 波形仍按连续原始样本计数器绘制；有效录制秒数按有效样本数除以 Hz 计算，允许非零起点与零起点。

## Scope and risks
内部方法签名及全部调用方、相关夹具同步更新；不改原始写入、设备状态机、公共 API 或科学计算。涉及文件保持在 400 行目标内。使用确定性样本批次覆盖两个 UI 入口；硬件操作延迟不由单元测试替代。

## Validation
先运行新回归确认旧代码失败，再验证首次样本前录制/暂停/恢复、真实边界与无边界路径、持续多轮暂停、实时波形连续性。运行相关桌面领域、桌面全量、后端 gate、规模和 diff 检查及 OpenSpec strict 校验；记录实际结果。
