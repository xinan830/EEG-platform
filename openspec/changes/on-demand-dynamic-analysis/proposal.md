# 按需动态分析窗口

## Why

当前动态算法通过完整 `AnalysisRun` 生成所选范围内的全部窗口，通常要等整段计算和 artifact 发布后，回溯或详情页才能读取任意窗口。长记录的等待体验差，也会计算用户没有播放或跳转到的窗口。

目标是在离线记录中，游标移动时确保目标窗口的科学结果可用；优先返回目标结果，向前播放时只允许有限预取。结果仍由后端算法模块计算、持久化并说明来源。算法公式、窗口策略、质量状态和预处理语义不得因按需执行而改变。

## Scope

- 新增算法无关的动态窗口能力协议、按需请求/状态/结果契约及有界调度/持久化机制。
- 先以 PSD 完成后端端到端垂直切片，再接入回溯与算法详情页；两个页面复用同一窗口服务、身份和缓存规则。
- 后续动态算法按能力声明逐个接入；每个算法必须证明单窗输出等价于其既有完整动态 Run 的同一窗口。无能力声明的算法继续使用现有完整 Run。
- 保留现有完整 Run、历史 artifact、导出、结构化预览和 `window-preview` API，不迁移或覆写历史结果。

## Non-goals

- 不改变任何算法的数学定义、窗口对齐/尾窗策略、质量门、输出单位或科学版本。
- 不把离线 zero-phase 结果称为实时或因果结果；不在此变更中改为 causal filtering、单窗滤波或新的边界处理。
- 不改原始录制、采集链路、回溯唯一播放时钟或在 WPF 中实现科学计算。
- 不提供无界并发、无界预取、无界内存/磁盘缓存，也不要求首窗必然显著快于完整 Run。

## Compatibility and migration

新增 API 和可重建的派生窗口存储；旧 `/api/runs`、`/api/runs/ensure`、artifact、导出和已完成 Run 的窗口读取保持原语义。旧完整 Run 不自动改写成按需会话，也不因用户关闭页面而删除。未声明按需能力的算法保持既有执行路径。功能可按算法能力开关关闭并回退完整 Run；回退不得删除已发布的不可变窗口或原始数据。

## Scientific-contract impact

本变更要求同源、同配置、同科学/实现身份下，按需 PSD 窗口与完整动态 PSD Run 的对应窗口数值、样本范围、轴、单位、质量状态、证据和预处理 provenance 在既定容差内一致。PSD 继续使用当前连续记录零相位预处理语义；按需只跳过未请求窗口的计算/结果生成，不通过缩短 EEG 读取范围来优化首窗。

`RecordingRelativeSampleIndex` 为权威游标坐标，窗口为后端决定的半开区间 `[start_sample, end_sample)`。缺数、gap、拒绝、部分窗口、取消和执行错误均保留为不同结构状态；不可用数值为 null，不得用 0 或较早有效窗冒充目标窗。

## Risks and decision gates

- 整段连续零相位预处理可能仍主导冷首窗延迟。P0/P4 分别测读取、预处理、窗口算法、持久化和 UI 等待，不预先承诺延迟收益。
- 新增持久化身份、并发去重、共享取消和崩溃恢复涉及一致性风险；P0 冻结所有权、项目边界、原子发布和恢复契约后，才开始行为实现。
- PSD P1 单窗对照、并发/取消/恢复与旧 API 回归通过前，不进入 WPF 切换；PSD GUI 和小时级资源验收通过前，不批量迁移其它算法。
- FAA 等具有不同预处理契约的算法必须独立适配和对照，不因使用同一调度协议而强制共享预处理实现。

## Rollback

按算法关闭按需能力即可返回现有完整 Run；保留旧 API 和 UI 入口。按需任务停止后不得发布半成品；派生缓存/索引可在验证身份后删除并重建。不可变已发布窗口和历史 Run 可继续读取，原始记录永不修改。
