## Why

当前播放、波形预览、RBP/TNK 实时分析和结果追加分别拥有部分调度逻辑，导致旧任务积压、取消释放不及时、结果按完成顺序到达以及时间轴出现空白。现在继续接入更多 TNK 指标会扩大不确定性，因此需要先建立一个以 RBP 为第一条闭环的统一、可观测、有界调度路径。

## What Changes

- 建立统一的播放时钟和窗口目标入口；算法、波形和游标不再各自推进时间。
- 建立有界调度器，分别管理波形预览、窗口独立算法、TNK 有状态算法和批量分析。
- 以 RBP 堆叠图作为第一条纵向闭环：共享数据准备、RBP 计算、结果缓存、按记录时间追加和图表发布。
- 对同一窗口实施精确去重：原始数据读取和公共预处理最多一次，算法专属预处理按明确契约执行。
- 明确旧目标取消、资源释放、结果排序、缺失窗口和计算延迟的生命周期语义。
- 为每个窗口记录 queued、prepared、computed、published、cancelled、failed 等阶段和时间指标。
- 在 RBP 闭环通过真实录音回放验收前，暂停新增 TNK 指标的实时接入。
- 为后续无状态算法和有状态算法分别定义适配边界，不把 RBP 的窗口独立逻辑强行套用于 TNK 状态链。

## Capabilities

### New Capabilities

- `analysis/unified-review-scheduler`: 定义统一播放时钟、任务分类、有界队列、去重、取消、资源预算和结果发布契约。
- `analysis/rbp-review-pipeline`: 定义 RBP 作为首个实时回放算法的共享准备、窗口计算、按时间追加和缺失状态语义。

### Modified Capabilities

- `viewer/waveform-playback`: 波形预览继续独立于科学计算，并改为订阅统一播放时钟和调度器产生的显示目标。
- `analysis/on-demand-windows`: 将现有按需窗口生命周期与统一调度器的任务去重、取消、资源容量和结果发布规则对齐。

## Impact

涉及 WPF 播放时钟、波形预览订阅、动态窗口协调器、RBP 后端执行路径、共享预处理缓存、结果历史投影、WebSocket/HTTP 窗口状态和诊断日志。公共科学结果需要保留采样率、单位、通道顺序、recording/montage 身份、半开窗口边界和算法版本。该变更不引入 Dask、Celery、Redis、LSL 或 BrainFlow，不改变原始 EEG 保存语义，也不把工程性能验收表述为临床验证。现有全量 Analysis Run 保持兼容；RBP 先以独立开关和真实录音验收，其他算法在后续阶段逐个迁移。

兼容迁移策略是先保留现有接口和旧结果读取能力，在 RBP 新路径通过自动化测试、日志指标和 WPF/真实录音验收后，再逐个启用算法适配器。失败或回滚时，调度器应停止新实时任务而不删除已发布科学结果。
