# 设计

## 单一引用所有者

`MontageRecordingReferences` 负责现存记录发现与索引；`MontageProfileStore`
负责保存/删除/采集发布的串行校验；UI 只绑定其返回权限，不独立计数。

版本 2 索引包含历史 ID、未定位引用 ID、已登记扫描根目录与记录位置。
历史 ID 决定编辑锁；重新扫描得到的现存 ID 与未定位 ID 决定删除锁。
刷新不修改 raw manifest。原子更新索引；扫描失败不能发布清空的状态。

旧数组升级只保留历史锁，并从已知项目和回收目录重建现存引用。历史锁
继续阻止旧草稿覆盖或复用已删除的 ID。旧版未知外部文件是显式迁移限制，
不能宣称扫描到了全磁盘的每份复制品。

## 采集与回溯

采集在同一存储变更锁下校验预设、登记位置、写入索引并发布 manifest，
消除“登记后 manifest 尚未出现”被当作可删除的间隙。路径为空的内部登记
仍按未定位引用保护。外部回溯登记实际记录目录。

保留已扫描项目根目录；项目从列表移除但文件仍在时，引用保持。记录移动
到项目回收目录后仍被发现。最后一个目录确实删除且扫描成功后，只解除
删除限制，历史版本不恢复为可覆盖。

## 失败行为

离线卷、权限错误、损坏索引/manifest、记录目录仍有文件却缺少 manifest
都返回明确验证错误。目录完全不存在或空目录可以确认无记录引用。
不删除原始文件，不以默认零值掩盖不确定引用。
索引必须包含版本 2 的全部字段且历史 ID 覆盖所有登记 ID；路径统一去除
非根目录的末尾分隔符，同一记录路径不得被登记为冲突的导联身份。
旧桌面程序不能读取版本 2 索引；更新后仅使用新构建，不删除索引回退。

## 规模与边界

索引模型与 JSON 迁移独立于扫描器；不扩展既有超大工作区职责。主窗口仅
传递已经持有的记录路径，参数和权限保持导联模块负责。
